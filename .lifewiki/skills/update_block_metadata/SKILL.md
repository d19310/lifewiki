# update_block_metadata

## 基本信息

- **名称**: update_block_metadata
- **功能**: 更新 block 的元数据（领域标签、分类状态等）
- **调用时机**: Step 5 分析总结 — AI 分析完成后更新 block 的领域标签

## 输入参数

```json
{
  "blockId": "block-uuid",
  "updates": {
    "category": "工作",
    "areas": ["工作", "学习"]
  }
}
```

### 可更新字段

| 字段 | 类型 | 说明 |
|------|------|------|
| category | `工作` \| `个人` \| `待确认` | 主分类 |
| areas | string[] | 领域标签数组，可包含多个 |

## 输出格式

```json
{
  "success": true,
  "data": {
    "blockId": "block-uuid",
    "updated": {
      "category": "工作",
      "areas": ["工作", "学习"]
    }
  }
}
```

## 领域判断规则

AI 根据以下规则判断 block 所属领域：

### 领域定义

| 领域 | 判断标准 | 关键词 |
|------|---------|--------|
| 工作 | 与工作任务、项目、会议、客户相关 | 项目、会议、客户、报告、汇报、老板、同事、工作、职场、加班 |
| 个人 | 与私人生活、家庭、朋友相关 | 朋友、家人、聚会、旅游、娱乐、休息、个人、家庭 |
| 学习 | 与学习、知识、技能提升相关 | 学习、读书、课程、培训、研究、论文、考试 |
| 其他 | 不属于以上三类 | - |

### 判断优先级

1. 如果日记内容主要涉及工作任务 → `工作`
2. 如果主要涉及私人生活 → `个人`
3. 如果主要涉及学习活动 → `学习`
4. 否则 → `其他`

### 多领域判断

如果日记涉及多个领域，可以设置多个 areas：
```json
{
  "category": "工作",
  "areas": ["工作", "学习"]
}
```

## 总结生成规则

Step 5 总结应包含：

1. **一句话总结**：简述本次分析的核心内容（不超过 50 字）
2. **涉及实体**：提到哪些类型的实体（人、项目、想法等）
3. **领域标签**：根据领域判断规则确定

### 总结模板

```
分析完成。本条日记涉及[核心内容]。

#领域标签
```

示例：
```
分析完成。本条日记涉及与张三、李四的会议讨论，以及华为项目的进展汇报。

#工作
```

## 执行流程

### Step 5 分析总结完整流程

1. **生成总结** - 根据日记内容生成简短总结
2. **判断领域** - 根据领域判断规则确定 category 和 areas
3. **更新元数据** - 调用 `update_block_metadata` 更新 block 领域标签
4. **结束分析** - 返回总结结果

### 执行步骤

1. 解析 blockId
2. 根据领域规则判断 category 和 areas
3. 调用底层 API 更新 block 元数据
4. 返回更新结果

## 错误处理

- **blockId 无效**: 返回错误 `block not found`
- **无效的 category**: 返回错误 `invalid category`
- **更新失败**: 返回错误并附带日志

## 与 Step 5 配合使用

```
Step 4 完成后 → Step 5 开始
  │
  ├─→ 生成一句话总结
  ├─→ 判断领域（工作/个人/学习/其他）
  ├─→ 调用 update_block_metadata 更新 block 领域标签
  │
  └─→ 结束分析，返回总结结果
```

## 禁止虚假声明

**绝对禁止**：在没有调用工具获得成功结果之前，在回复中声称"已更新领域标签"。

**正确做法**：必须先调用 update_block_metadata → 获得成功结果 → 才能在回复中说"已更新"。
