# link_entities

## 基本信息

- **名称**: link_entities
- **功能**: 批量发现并建立实体间的关联关系
- **调用时机**: Step 3 关系发现 — AI 分析实体间关系，用户确认后批量建立关联

## 输入参数

```json
{
  "links": [
    {
      "entityIdA": "entity-uuid",
      "entityIdB": "entity-uuid",
      "relation": "负责人",
      "context": "日记中提到 A 负责 B 的工作"
    }
  ],
  "options": {
    "autoConfirmHighConfidence": true
  }
}
```

### 批量关联

`links` 数组支持一次传入多对关联，一次调用完成所有关联建立。

## 输出格式

```json
{
  "success": true,
  "results": {
    "linked": [
      {
        "entityIdA": "xxx",
        "entityIdB": "yyy",
        "relation": "负责人",
        "success": true
      }
    ],
    "errors": [
      {
        "entityIdA": "xxx",
        "entityIdB": "zzz",
        "error": "entity not found",
        "success": false
      }
    ]
  },
  "summary": {
    "totalLinked": 1,
    "totalErrors": 1
  }
}
```

## 关系类型（扩展版）

| 关系 | 说明 | 适用实体类型 |
|------|------|-------------|
| 负责人 | A 是 B 的负责人 | person → project/thing |
| 成员 | A 是 B 的成员 | person → project |
| 相关 | A 与 B 相关 | 通用 |
| 同一项目 | A 和 B 属于同一项目 | project ↔ project |
| 同一任务 | A 和 B 属于同一任务 | project ↔ project |
| 属于 | A 属于 B（组织/类别） | 通用 |
| 包含 | A 包含 B | 通用 |
| 对立 | A 与 B 对立 | 通用 |
| 上下游 | A 是 B 的上游/下游 | 通用 |
| 合作 | A 与 B 合作 | 通用 |
| 替代 | A 可替代 B | thing ↔ thing |
| 组成 | A 是 B 的组成部分 | thing ↔ thing |

## 关系推断规则

AI Agent 根据以下规则自动推断实体间关系：

### 规则表

| 条件 | 推断关系 | 示例 |
|------|---------|------|
| person + project + 提到"负责/主导" | 负责人 | 张三 + 华为项目 → 张三负责华为项目 |
| person + project + 提到"参与/成员" | 成员 | 李四 + 华为项目 → 李四是成员 |
| 两个 project + 同一上下文提到 | 同一项目/同一任务 | 华为项目 + 荣耀项目 → 同一项目 |
| person/thing + 提到"属于/旗下" | 属于 | 华为 + 华为项目 → 华为项目属于华为 |
| 两个 thing + 提到"组成/部分" | 组成 | 屏幕 + 手机 → 屏幕是手机组成部分 |
| 提到"合作/协作" | 合作 | 张三 + 李四 → 合作关系 |
| 提到"替代/取代" | 替代 | 新手机 + 旧手机 → 替代关系 |

### 关系方向规则

| relation | 正向（A→B） | 反向（B→A） |
|----------|-----------|-------------|
| 负责人 | 负责人 | 成员 |
| 成员 | 成员 | 负责人 |
| 同一项目 | 同一项目 | 同一项目 |
| 同一任务 | 同一任务 | 同一任务 |
| 属于 | 属于 | 包含 |
| 包含 | 包含 | 属于 |
| 对立 | 对立 | 对立 |
| 上下游 | 上游/下游 | 下游/上游 |
| 合作 | 合作 | 合作 |
| 替代 | 替代 | 被替代 |
| 组成 | 组成 | 的组成部分 |

## 执行流程

### Step 3 关系发现完整流程

1. **AI 分析** - 根据关系推断规则，分析实体间的潜在关系
2. **展示结果** - 将分析结果以简洁方式展示给用户
3. **用户确认** - 用户确认、修改或补充关系
4. **批量执行** - 调用 `link_entities` 一次建立所有确认的关联

### 执行步骤

1. 解析 `links` 数组
2. 对每对关联验证实体存在性
3. 批量执行双向关联建立
4. 返回每个操作的结果

## 错误处理

- **entityId 无效**: 返回错误但不中断其他操作
- **关联失败**: 返回错误，包含具体原因
- **部分成功**: 继续处理其他关联，最终返回完整结果

## 禁止虚假声明

**绝对禁止**：在没有调用工具获得成功结果之前，在回复中声称"已关联"、"已建立关系"。

**正确做法**：必须先调用 link_entities → 获得成功结果 → 才能在回复中说"已关联"。
